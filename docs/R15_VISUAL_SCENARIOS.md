# v1.1.3 / r15 — сравнение до/после и пользовательские сценарии

Это дополнение к исправлениям безопасности Fix Bridge r14. Сборка предназначена для чистой папки на Windows 10/11 x64 с Node.js >=22.19.0; старую установленную папку не заменяйте поверх файлов. Архив содержит исходники и lockfile, а не готовые `node_modules`/`dist`.

## Сравнение до и после

1. Запустите обычный аудит публичного сайта. Дождитесь итогового отчёта и полного набора снимков выбранных экранов.
2. В разделе «До / после» нажмите «Утвердить текущий аудит как эталон». Действие явное: программа не меняет эталон при следующем аудите.
3. После изменений сайта и деплоя запустите новый аудит того же URL с теми же размерами. В истории выберите новый аудит, выберите эталон и нажмите «Сравнить».
4. Посмотрите снимки «До», «После» и красную карту различий. `REVIEW` означает пиксельные отличия, требующие человека; `UNCHANGED` означает отсутствие отличий выше порога 20/255 на сопоставимых снимках. `NOT_COMPARABLE` означает несовпадение условий или недоступные снимки. Ни один из этих статусов сам по себе не подтверждает отсутствие функциональных ошибок.

Эталон копируется в локальную папку `baselines`, связывается с завершённым аудитом и снабжается хэшами и локальной подписью метаданных. Исходный URL, ОС, версия Chromium и параметры каждого viewport должны совпадать. Картинки и результат сравнения хранятся локально; эти папки не включаются в исходный ZIP. Живые часы, анимации, персонализация и реклама могут создавать отличия без бага. Неполный аудит нельзя утверждать как эталон.

## Проверка пользовательского сценария

1. Укажите публичный URL, название и размер экрана.
2. Добавьте от 1 до 12 шагов. Каждый CSS-селектор должен выбрать ровно один элемент. Доступны «Проверить видимость», «Проверить текст», «Открыть меню / вкладку», «Выбрать checkbox / radio», «Ввести тестовый текст».
3. Используйте только вымышленные значения. Нажмите «Запустить безопасный сценарий». Изучите статус каждого шага, локальные снимки и trace. Файл JSON позволяет вручную сохранить и открыть последовательность.

Сценарий загружает публичную страницу в одноразовом Chromium с Safe Mode, затем блокирует всю сеть до конца шагов. Ссылки, отправка форм, оплата и опасные сигналы действия пропускаются с `SKIPPED_SAFELY`. `PASS` относится только к указанным шагам и возможен, только если ни один блок сети не сделал проверку неполной. Код самой страницы может реагировать на разрешённое действие внутри одноразового браузера; эта функция не предназначена для административных/авторизованных сценариев, проверки покупки или многостраничных переходов. Полностью изолированной ОС песочницы здесь нет.

Скриншоты, trace и сохранённый JSON **могут содержать видимый текст, введённые значения и персональные данные**. Пиксели изображений не редактируются автоматически. Перед передачей файлов третьим лицам их нужно просмотреть.

## Проверка этой версии

В Linux/Node 24.19.0 проверены unit и security regression tests, сборка, production runtime smoke (в том числе API эталона и четырёх размеров UI). Сценарные действия проверены в контролируемой странице. Полноценный запуск сценария на внешнем реальном сайте и нативная Windows установка/`RUN.bat`/`VERIFY.bat` **NOT VERIFIED** в этом окружении. У пользователя сейчас нет возможности проверить Windows; эта проверка отложена, а не засчитана как PASS.

Когда Windows будет доступна: распакуйте ZIP в новую папку, запустите `RUN.bat`, сохраните `final-verification.log`, затем `VERIFY.bat`. Дополнительно выполните `npm.cmd run static:check`, `npm.cmd run typecheck`, `npm.cmd test`, `npm.cmd run build`, `npm.cmd run smoke:runtime`, `npm.cmd run benchmark:accuracy`, `npm.cmd run verify`. Проверьте на своём публичном тестовом сайте эталон и безопасный сценарий. При ошибке сохраните лог, статус останется NOT VERIFIED/FAILED до устранения причины.
