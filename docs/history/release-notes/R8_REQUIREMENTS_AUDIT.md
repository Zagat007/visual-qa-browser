# Visual QA Browser: 14 углублённых аудитов требований и работы

Дата: 2026-10-02. Ревизия: r8 (поверх объединённого r7). Статус ниже относится к исходникам и контролируемым фикстурам. Ссылка на опубликованный соседний чат не открылась в среде проверки; требования восстановлены из доступного контекста беседы, проектной документации и конфигурации. Нет доступа к целевому сайту, его исходникам, закрытым страницам и Windows машине пользователя.

## Метод и проверка

- Сопоставлены исходные требования: локальный Windows инструмент, безопасный live аудит, технические модули, адаптивность и Art Director, доказательства, GPT передача, очередь, отмена, отсутствие ложного PASS и стремление к полноте по страницам/состояниям/исходникам.
- Просмотрены `app/frontend/src`, `app/backend/src`, `audit-engine`, `configs`, Windows скрипты и документация. Выполнен `npm run verify` на Linux Node 24.19.0 с Chromium 140: static 91/91, typecheck, 27 файлов/111 тестов, production build, серверный и UI smoke — PASS. Полный набор тестов содержит управляемый FULL STANDARD/FAST сценарий девяти модулей, шести viewport и трёх реальных Lighthouse прогонов. Эти результаты подтверждают именно проверенные сценарии, а не полноту детектора.
- Не проводилась оценка precision/recall на размеченном корпусе реальных сайтов. Не запускался `RUN.bat`/`STOP.bat` на Windows. Проверка опубликованного чата и приватных страниц не состоялась. Поэтому «безупречно» и «находит все баги» не подтверждены.

## Подтверждённый дефект r7 и исправление r8

`audit-engine/reporting/report.ts` задаёт responsive finding viewport строкой диапазона (`320→370px`), а `audit-engine/reporting/handoff.ts` подбирал screenshots только по имени захваченного viewport (`desktop-1440`). При единственном BUG от sweep и выключенном Art Director ZIP мог не содержать ни одного изображения. r8 добавляет ближайший захваченный screenshot в ZIP, отмечает сопоставление в `approximateScreenshotMatches` и оставляет BUG в `issuesWithoutExactViewportScreenshot`. Регрессионный тест `tests/report.test.ts` моделирует этот случай. Кадр 1440 px не является доказательством overflow на 320–370 px; GPT обязан воспроизвести точную ширину. Приоритет следующего улучшения — автоматически снять кадр на ширине находки, если это разрешено и безопасно.

## Приоритеты доработки

1. **P1 — честный scope в UI:** переименовать/пояснить «Проверить всё» как «все доступные проверки текущего URL»; показать до запуска выбранные viewport, KEY/ALL, Art OFF и исключённые возможности. В отчёте перечислить, какие страницы и состояния не посещались.
2. **P1 — точные доказательства:** переснимать найденные sweep ширины/состояния с URL и timestamp, связывать каждый BUG с кадром, DOM selector/network/console evidence и репродукцией; GPT пакет проверять на полноту перед выгрузкой.
3. **P1 — измерить точность:** создать размеченный корпус реальных сайтов с известными дефектами и негативными примерами; измерять precision, recall, пропуски, FP по каждому правилу/viewport, повторять после изменений. Текущие unit/fixture тесты этого не измеряют.
4. **P2 — охват сайта:** управляемый crawler публичных страниц, сценарии состояний и конфигурация авторизованного доступа с безопасной изоляцией; coverage-denominator, явный статус для непосещённых страниц.
5. **P2 — source/baseline:** отдельные source/CSS проверки, базовые скриншоты и diff с контролем динамического контента; объединение live и source evidence без объявления эвристик подтверждёнными дефектами.
6. **P2 — защита и платформа:** сетевой proxy/IP pinning или изоляция для закрытия DNS TOCTOU; целевой Windows acceptance r8 с антивирусом пользователя и реальным сценарием start, cancel, STOP, restart.

## Практический вывод

Текущая версия пригодна как локальный диагностический инструмент для разрешённого публичного URL и зафиксированных размеров. Она не может гарантировать выявление всех визуальных, функциональных или security дефектов сайта. `PASS` означает отсутствие обнаруженных проблем в выполненном scope; `NOT VERIFIED` сохраняется для непроверенных страниц, Windows r8 и точности на реальных сайтах. Для исправления GPT передавайте prompt + `gpt-evidence.zip` + исходники целевого сайта, проверяйте BUG-ID и открытые изображения, а CAND сначала воспроизводите.
