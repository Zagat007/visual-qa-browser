# r9 — точное доказательство responsive overflow

Дата: 2026-10-02. Изменения основаны на 14 аудитах r8 (`R8_REQUIREMENTS_AUDIT.md`).

## Первопричина и исправление

Раньше responsive sweep измерял overflow на отдельных ширинах, но делал скриншоты только для основной матрицы viewport. Поэтому BUG на 320 px мог сопровождаться кадром на 1440 px или не иметь изображения в GPT ZIP.

Теперь после первого измерения каждый HIGH `responsive-overflow` повторно проверяется в том же браузерном контексте Safe Mode на **точной ширине**. После стабилизации измеряется фактический overflow, сохраняется PNG и фиксируются ширина, значение, время, итоговый URL и путь кадра. Только успешный повтор с overflow >2 px и сохранённым PNG получает `CONFIRMED` и BUG. Неповторившийся сигнал становится CAND и переводит общий статус в `PARTIAL`; сбой повторной проверки также даёт CAND/`PARTIAL`. Остальные эвристические responsive-находки остаются CAND.

В `gpt-evidence.zip` точные responsive PNG получают приоритет перед остальными изображениями. Манифест связывает кадр с BUG-ID и перечисляет пропущенные файлы, если достигнут общий лимит 48 MiB или файл недоступен. ZIP, отчёт и prompt не заменяют проверки причины по исходникам сайта.

Режим FULL теперь называется «Все проверки URL»; описание и справка явно говорят о текущем URL, выбранных размерах, ограниченной глубине взаимодействий и выключенном по умолчанию Art Director.

## Проверка

- `npm run verify` на Linux Node 24.19.0 / Chromium 140: static 91/91, typecheck PASS, 27 файлов / **113 тестов PASS**, production frontend/backend build PASS, runtime/UI smoke PASS.
- Chromium fixture: overflow 60 px на 320 px; повторный замер, реальный PNG `responsive/width-320.png`, BUG и ZIP PASS.
- Искусственно неповторившийся сигнал: `defects.json=[]`, CAND, итог `PARTIAL` PASS.
- `tests/report.test.ts`: exact-width screenshot и случай без повторения PASS.

## Границы

Два одинаковых геометрических замера и PNG подтверждают **горизонтальный overflow**, но не устанавливают его CSS первопричину и не доказывают, что пользователь увидит дефект в каждом состоянии страницы. Некоторые длинные карусели могут требовать отдельного визуального рассмотрения. Проверяется один URL; нет обхода всех страниц, source forensics или visual baseline. ZIP ограничен 48 MiB изображений; каждый пропуск отмечается в манифесте. Windows r9 на машине пользователя, влияние антивируса и точность на размеченном корпусе сайтов остаются **NOT VERIFIED**.
